## 3. How agent.md is templated/generated by the CLI

**There is no special-casing of `agent.md` anywhere in the CLI.** Grepping the entire Go source (`internal/`, `cmd/`) for `agent.md` and `Taskfile` returns nothing. `agent.md.tmpl` is just an ordinary skeleton file rendered by the generic engine:

- `/Users/robinhultman/dev/intropy/tooling/intropy-cli/internal/blueprint/render.go` — `Render()` walks `skeleton/`, runs every path segment through Go `text/template` + sprig, and renders file contents only when the basename ends in `.tmpl` (suffix stripped on output). So `agent.md.tmpl` → `agent.md` with `{{ .name }}`, `{{ .appId }}`, `{{ .name | kebabcase }}` substituted. Renderer uses `missingkey=error`.
- `/Users/robinhultman/dev/intropy/tooling/intropy-cli/internal/blueprint/create.go` — `Create()` orchestrates: resolve release tag → download tarball → extract → `LoadTemplate(template.yaml)` → `Resolve` values (flags/files/prompt) → `Render(skeleton, outputDir, values)`. `renderCreateOutput` requires the `skeleton/` dir; no per-file logic.
- Data context is a flat map of the manifest `parameters` + derived `spec.values`. From `template.yaml`: `name` (required, PascalCase; transactional also has `empty` boolean) and derived `appId: '{{ .name | kebabcase | replace "." "-" }}'`.

So agent.md's content is entirely owned by the blueprint repo; the CLI treats it as opaque skeleton content.
