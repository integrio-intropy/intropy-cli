## Overview

`intropy run` (aliased as `int run`) starts a local, read-only web dashboard that visualizes integrations scaffolded under a workspace directory. It embeds a React/Vite SPA into the Go binary and serves it plus a small JSON API from a stdlib `net/http` server. It starts no integration processes.

Data flows from three on-disk sources: per-project `.intropy/scaffold.json` records (the primary source), per-system `.intropy/topology.json` records (new, optional), and best-effort enrichment files (AGENTS.md, README.md, Dapr component YAML, pipeline step files).

## 5. Data flow: `intropy run` → data load → render

1. `int run [dir]` (`int_run.go`) validates the dir and calls `dashboard.Serve` with Root = that dir.
2. `Serve` (`server.go`) builds the mux (`newHandler`), binds the socket, opens the browser, and serves the embedded SPA (`web.Assets` → `dist/`) plus the JSON API.
3. The SPA (`App.tsx`) on load calls `GET /api/integrations` and `GET /api/health`. The Flow view (`FlowView.tsx`) calls `GET /api/flow` and `GET /api/topology`.
4. Server side, all three data endpoints walk the Root directory:
   - `/api/integrations` and `/api/integrations/{path}` → `template.ListScaffolds(root)` reads every `.intropy/scaffold.json` (the primary catalog data). Detail requests additionally read `AGENTS.md`, `README.md`, `local/dapr-components/*.yaml`, and `src/Process/Steps/*`.
   - `/api/flow` → same scaffold list plus Dapr components and pipeline steps for each node.
   - `/api/topology` → `topology.List(root)` reads every `.intropy/topology.json`.
5. Rendering:
   - The Catalog view renders the scaffold entries in the Sidebar (grouped by derived Domain/System/Name) and the selected integration in the DetailPanel (scaffold values + AGENTS/README/components/steps).
   - The Flow view groups integrations by system, then per system calls `topologyFor(items, topologies)` (`FlowView.tsx` lines 139-152) to find the declared `topology.json` whose directory contains all of the group's integrations (a record at `.` covers everything). If a declared topology matches, it renders the declared graph (`buildDeclaredGraph`, ~line 481) using its components/resources/apis/edges, and uses `system.name` as the authoritative label. If no topology record matches, it falls back to component-derived heuristics built from the `/api/flow` Dapr components and the `dataFlow` field on the scaffold.

So: the dashboard's core data is `scaffold.json` (always), enriched by on-disk files, with `topology.json` as a newer, optional overlay that drives the authoritative flow graph when present. The topology and scaffold records are matched purely by root-relative directory path (`relPath` on the Go side, path-prefix matching in `topologyFor` on the frontend).

Note: no `intropy run` code writes any file — it is strictly read-only, consistent with the package docs.</result>
