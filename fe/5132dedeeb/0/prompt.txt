## 3. Topology output format

**`topology.intropy.io/v1` does not exist in the CLI repo.** The only file in your whole tree with that `apiVersion` is a hand-authored example:

```json
{ "apiVersion": "topology.intropy.io/v1", "kind": "SystemTopology", "system": "distribution",
  "components": [ { "name": "extractor", "kind": "extractor",
      "subscribes": [], "publishes": [{"port":"b2c","pubsub":"price-pubsub","topic":"price-b2c"}],
      "provides": [], "consumes": [],
      "connectors": [{"connector":"price-master","direction":"in"}] } ],
```

**The critical design note for your work** — `Refs.cs:106-115`:

&gt; Only the connector's *name* is intrinsic to a component — it is the local port the component reads from or writes to. Both *what* it connects to (the external system) and *how* (the transport) are resolution concerns, **bound together at a later system-assembly step (`intropy system create`)**, not at block scaffolding (`intropy int create`). A connector declared by name only is *unresolved*… it surfaces as a warning (ITP107) rather than an error.

This is a written contract naming `intropy sys create` as the resolution point, and it is currently unimplemented.
