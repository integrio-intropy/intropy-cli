## 1. How `int create` scaffolds projects

Key fact: **templates are NOT embedded via `go:embed`.** There are zero `go:embed` directives in the codebase. Templates are fetched at runtime from a **remote GitHub repository** as release tarballs.

### Command entry point
`/Users/robinhultman/dev/intropy/tooling/intropy-cli/cmd/intropy/int_create.go` — the `int create &lt;template&gt;` Cobra command. It builds a `template.CreateOptions` and calls `template.Create(ctx, opts)`. After scaffolding it optionally installs the agent skills collection (`maybeInstallSkills`).

### Scaffold pipeline
`/Users/robinhultman/dev/intropy/tooling/intropy-cli/internal/template/create.go` — `Create()` (lines 66-109) runs the full flow:
1. `resolveReleaseTag` — resolve requested version or "latest" via GitHub API.
2. `downloadTemplate` — download repo tarball, extract to a temp dir, locate the named template subdirectory.
3. `prepareCreateTemplate` — load `template.yaml` manifest, resolve values (with interactive prompting).
4. `renderCreateOutput` — render the `skeleton/` subdirectory to the output dir.
5. `WriteScaffold` — write `.intropy/scaffold.json`.
6. `maybeWriteCreateResult` — optionally emit machine-readable `CreateResult` JSON (`--output-json`).

### Remote source


Each template in the remote repo has a `template.yaml` manifest plus a `skeleton/` directory that gets rendered. Other relevant files: `internal/template/render.go` (renders skeleton, using `Masterminds/sprig` templating), `internal/template/archive.go` (`ExtractTarGz`), `internal/template/values.go` + `prompt.go` (value resolution/prompting), `internal/template/manifest.go` (manifest model, below).

## 3. Detecting &amp; modeling `.intropy/scaffold.json` (the `int list` command)

Command: `/Users/robinhultman/dev/intropy/tooling/intropy-cli/cmd/intropy/int_list.go` — `int list [dir]`. Validates `--output` (json/plain), calls `template.ListScaffolds(root)`, prints a tabwriter table (`PATH / TEMPLATE / VERSION`) or JSON array.

Walker + model: `/Users/robinhultman/dev/intropy/tooling/intropy-cli/internal/template/scaffold_list.go`:
```go
var listSkipDirs = map[string]bool{
	".git": true, ".intropy": true, "node_modules": true, "bin": true, "dist": true,
}

type ScaffoldEntry struct {
	Path string `json:"path"`
	Scaffold          // embedded — flattens into the JSON document
}

func ListScaffolds(root string) (entries []ScaffoldEntry, warnings []error)
```
`ListScaffolds` uses `filepath.WalkDir`, skips the dirs above, and for each directory checks for `.intropy/scaffold.json`. On a match it `LoadScaffold`s the record, appends a `ScaffoldEntry`, and returns `fs.SkipDir` (projects don't nest). Malformed records / unreadable dirs become non-fatal warnings. The `Scaffold` struct is embedded so each entry serializes as one flat self-describing JSON object (path + all scaffold fields).

This walk-and-collect pattern is directly reusable if the dashboard needs to enumerate all integrations under a workspace.

- **Browser opening:** no dependency. Would need `github.com/pkg/browser` or a small `os/exec` wrapper (`open`/`xdg-open`/`start`).
- **Subprocess (`os/exec`):** already used in exactly one place — `/Users/robinhultman/dev/intropy/tooling/intropy-cli/cmd/intropy/skills_publish.go:84` (`exec.Command("cosign", "sign", ...)`). So there is precedent for shelling out (useful for launching `vite`/`npm`).
