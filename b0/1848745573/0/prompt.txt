## Summary: the flow/topology diagram is rendered client-side by React Flow (`@xyflow/react` v12)

The Go CLI does **not** render diagrams. It only serves JSON over HTTP and serves an embedded React SPA. All diagram drawing happens in the browser using the **React Flow** library (`@xyflow/react`). This is a DOM + SVG hybrid renderer: nodes are plain React components (HTML `&lt;div&gt;`s styled with CSS), and edges/handles/arrowheads are SVG paths that React Flow generates. There is no Mermaid, D3-force, dagre, elkjs, cytoscape, or graphviz driving layout — layout is computed by hand in TypeScript.

### Feasibility note for a "hand-drawn"/sketchy aesthetic

Because rendering is **React Flow (DOM nodes + generated SVG edges)** and not a monolithic library like Mermaid, a sketchy look is achievable but touches two distinct layers:

- **Node cards** are HTML/CSS divs (`.rf-int`, `.rf-group`, etc.) — a sketchy look here means CSS (wobbly borders, hand-drawn fonts, filter/texture) or swapping the node components in `NODE_TYPES` for custom-drawn SVG (e.g. rough.js). No library fights you here; you fully own these components.
- **Edges** are SVG paths React Flow computes (Bezier by default). CSS `stroke`/`stroke-dasharray` styling is easy (already used), but a true rough/sketchy stroke requires a **custom edge type** in React Flow (an `edgeTypes` map — not currently defined; edges use the default type) that renders a rough.js-style path instead of React Flow's smooth path. React Flow fully supports custom edge components, so this is feasible.
- The two hand-written layout functions (`buildGraph`, `buildDeclaredGraph`) produce fixed x/y coordinates, so a sketchy restyle does not disturb layout — it is purely a rendering-layer change in `FlowView.tsx` + `index.css`.
