## 2. How integrations are discovered and modeled

**Discovery is entirely driven by `.intropy/scaffold.json`.** The backend does NOT read Backstage catalog, `match.json`, or Dapr YAML for discovery.

- Core walker: `template.ListScaffolds(root)` in `/Users/robinhultman/dev/intropy/tooling/intropy-cli/internal/template/scaffold_list.go`. Walks the tree, and for every directory containing `.intropy/scaffold.json` yields a `ScaffoldEntry`. Skips `.git`, `.intropy`, `node_modules`, `bin`, `dist`; does not descend into a matched project (projects don't nest). This is the exact same primitive `int list` uses.

- The record model, `Scaffold`, in `/Users/robinhultman/dev/intropy/tooling/intropy-cli/internal/template/scaffold.go`:
```go

	SchemaVersion int            `json:"schemaVersion"`
	Template      string         `json:"template"`
	Owner         string         `json:"owner"`
	Repo          string         `json:"repo"`
	Version       string         `json:"version"`
	Values        map[string]any `json:"values"`
}
```
`ScaffoldEntry` = `{Path string}` + embedded `Scaffold`. Const `ScaffoldRelPath = ".intropy/scaffold.json"`.

**Dashboard's own models** (`handlers.go`):

## 3. Dapr components — what is read

Dapr YAML is **NOT parsed**. The backend only lists filenames. In `enrich` and `flow` (handlers.go):
```go
DaprComponents: listNames(filepath.Join(dir, "local", "dapr-components")),
PipelineSteps:  listNames(filepath.Join(dir, "src", "Process", "Steps")),
```
`listNames` (handlers.go) does `os.ReadDir` and returns sorted base filenames of the non-dir entries — nothing more. So `DaprComponents` is just e.g. `["local-storage.yaml", "pubsub.yaml"]` and `PipelineSteps` is the `.cs` step filenames.

The actual component YAML (`Orders/local/dapr-components/pubsub.yaml`, `local-storage.yaml`) contains rich data the backend ignores:

```yaml

No `dapr`/`pubsub`/`statestore`/`binding` YAML parsing exists in non-test Go code. The frontend (`FlowView.tsx` `componentName`) merely strips the `.yaml` extension from the filename for a chip label. **Greenfield: extracting component type / metadata / topics from the Dapr YAML does not exist yet.**

## 5. Overall data flow

```
.intropy/scaffold.json (on disk, per project)
   → template.ListScaffolds(root)            [walk, one entry per project]
   → []ScaffoldEntry {Path, Scaffold{template,owner,repo,version,values}}
   → apiServer.summarize()                   [derive name/system/domain from dir nesting; make Path root-relative]
   → apiServer.enrich() / flow()             [best-effort filesystem reads:]
         • AGENTS.md, README.md  → fileDoc (truncated to 128 KiB)
         • local/dapr-components/* → filenames only
         • src/Process/Steps/*     → filenames only
   → writeJSON (indented) over /api/integrations, /api/integrations/{path}, /api/flow
   → web/src/api.ts fetch → React SPA (Sidebar tree grouped by domain/system,
                                       FlowView canvas of grouped cards with step + component chips,
                                       DetailPanel showing scaffold fields + AGENTS/README)
```
The frontend TS types in `/Users/robinhultman/dev/intropy/tooling/intropy-cli/web/src/api.ts` (`Integration`, `IntegrationDetail`) exactly mirror the Go JSON contract.
