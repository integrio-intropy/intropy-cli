## 3. blockKind switches/maps — is "loader" handled everywhere?

There is no map keyed on blockKind anywhere; only three places branch on it:

1. `internal/system/assemble.go:46` — allow-list `{extractor, loader}`. Exact, case-sensitive string compare against `BlockKindExtractor = "extractor"` / `BlockKindLoader = "loader"` (`internal/template/scaffold.go:48-49`). Loader *is* handled; `reconciler`/`assembler` are deliberately unsupported and warn (`:47`).
2. `internal/system/codegen.go:85-89` — binary `if extractor / else loader`. The `else` is a **silent catch-all**: any kind that ever gets past the `Assemble` gate but isn't exactly `"extractor"` is emitted as `AddLoader(...).Subscribes(...)`. So a casing mismatch on the *extractor* side (`"Extractor"`) would today be rejected by `Assemble`; if that gate is ever loosened, the extractor becomes a loader silently.
3. `internal/template/{create.go:124, dependencies.go:140}` — pass-through copy of the label; no normalization (no `strings.ToLower`/`TrimSpace`). A template label of `Loader`, `LOADER`, or `loader ` would land verbatim in the record and then be skipped as "unsupported block kind" at `assemble.go:46`.

Additional silent-drop path worth flagging: the `switch` in `assemble.go:32-39` tests `Role` **before** `BlockKind`, and `RoleSharedLibrary` `continue`s with **no warning at all**. Any block template that gains a `intropy.dev/template-role` label would vanish from the system with zero output.

`dataFlow` (`"in"`/`"out"`) is recorded (`scaffold.go:76`, written at `create.go:125`) but read nowhere — grep confirms zero consumers. It is an available, unused signal for inferring/validating kind.

## 4. Topology/edge-based filtering

None. Topics are derived in the same loop that builds components (`assemble.go:73-83`), and `writeSystemClassFile` renders one edge per component with no edge/topology predicate. The only edge-adjacent risk is `fieldByKey[c.Topic]` (`codegen.go:84`): a Go map miss yields `""`, which would emit `.Subscribes(Topics.)` — uncompilable rather than dropped. Currently unreachable, because `fieldByKey` is built from the same `byTopic` map the components were keyed against.

Hard-error paths (not silent drops): duplicate `appId` (`assemble.go:68-70`), conflicting contracts on one topic key (`:74-77`), C# field-name collisions (`:111-117`), zero/multiple shared libraries (`:89-98`), missing `appId`/`topic`/`contract` values (`:51-66`).
