## 4. Transports / endpoints — "From" and "To" today

**There is no transport/connector/endpoint abstraction anywhere in the CLI, the scaffold record, or the template parameters.** No `from`, `to`, `transport`, or `connector` parameter exists. The only pipeline-level "edges" the model knows about are the *pub/sub topic* (`topic` + `pubsub`) — i.e. the internal system edge, not the external endpoint.

What actually exists is a **hardcoded FILE transport**, expressed in three places per component:

1. **Dapr binding component (local-storage), fixed name + fixed folder:**
   - `extractor/skeleton/local/dapr-components/inbound.yaml.tmpl` — `type: bindings.localstorage`, `name: inbound`, `rootPath: "./local/storage/inbound"`
   - `loader/skeleton/local/dapr-components/destination.yaml` — same, `name: destination`, `rootPath: "./local/storage/destination"`
   Note the extractor's is `.tmpl` but contains no template expressions; the loader's is plain YAML.

2. **Constants** (`extractor/.../Configuration/Constants.cs.tmpl:11,16`, `loader/...:11,13`): `InboundBindingName = "inbound"` / `SourceFileAdapterKey = "source"`; `DestinationBindingName = "destination"` / `DestinationFileAdapterKey = "destination"`. These are literals — **not** derived from any template parameter.

3. **DI registration** — `extractor/skeleton/src/Program.cs.tmpl:39-42` and `loader/skeleton/src/Program.cs.tmpl:41-44`:
```csharp
services.AddKeyedSingleton&lt;IFileAdapter&gt;(Constants.SourceFileAdapterKey, (sp,_) =&gt;
    new LocalFileAdapter(sp.GetRequiredService&lt;DaprClient&gt;(),
                         new FileAdapterOptions(Constants.InboundBindingName)));
```

The **extractor's "From"** is a poll loop, not a builder step: `ExtractorRunner.cs.tmpl:87-126` sweeps `fileAdapter.ListAsync()` every `Constants.PollIntervalSeconds` (5, hardcoded at `Constants.cs.tmpl:14`), reads content, injects `file_name` into `Context`, executes the pipeline, deletes on Success/Cancelled, leaves the file on failure for retry.

The **loader's "To"** is a pipeline step: `Sender.cs.tmpl:11-26` — `JsonSerializer.Serialize(input)` then `fileAdapter.WriteAsync($"{input.OrderId}.json", ...)`. Its "From" is the Dapr streaming subscription in `LoaderRunner.cs.tmpl:62-77`.

**The adapter abstraction already supports more transports than the templates use.** `/Users/robinhultman/dev/intropy/tooling/intropy-libs-framework/src/Intropy.Libs.Framework.Adapters/File/` contains `IFileAdapter.cs`, `LocalFileAdapter.cs`, `SftpAdapter.cs`, `AzureBlobStorageAdapter.cs`, and `FileAdapterOptions.cs` (`DaprBindingName`, `BasePath`, `FileNameRegex?`). Templates wire `LocalFileAdapter` only, and never use `BasePath`/`FileNameRegex`. That is the natural seam for a `transport` parameter: swap the adapter class + Dapr component YAML while keeping the keyed-service key and `Constants.*BindingName` stable.
