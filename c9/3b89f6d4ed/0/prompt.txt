## 4. What is off about the loader specifically

**Only difference: the two missing keys.** Every `values` entry is present and correctly cased (`appId: order-loader`, `contract: Order`, `topic: orders`, `pubsub: pubsub`, `name: OrderLoader`) — naming, casing, and `dependsOn` are all identical in form to the extractor. Nothing else differs.

**Why that kills registration** — `/Users/robinhultman/dev/intropy/tooling/intropy-cli/internal/system/assemble.go:43`:

```go
case e.BlockKind == "":
    warnf("skipping %s: scaffold record has no block kind — re-scaffold with a newer template release to include it", e.Path)
    continue
```

The warning goes to stderr as `warning: skipping order-loader: ...` (`internal/system/create.go:104-106`) — easy to miss in the create output. `internal/system/codegen.go:85` then only emits `AddLoader`/`Subscribes` for components that survived that filter.

**Why the field is missing — not a template bug.** The label exists in the templates repo at the exact version recorded (`v0.2.1-beta.5` = commit `dd78568`, local HEAD, clean tree) — `/Users/robinhultman/dev/intropy/tooling/intropy-templates/loader/template.yaml:12-15`:

```yaml
  labels:
    intropy.io/template-level: example
    intropy.dev/block-kind: loader
    intropy.dev/data-flow: "out"
```

The cause is **which binary wrote each record**:

| | mtime | writer |
|---|---|---|
| `/opt/homebrew/Caskroom/intropy/0.7.0/intropy` (what `intropy` on PATH resolves to) | installed 11:07 | `strings` contains `intropy.dev/template-role` and `dependsOn` but **zero** hits for `intropy.dev/block-kind`, `AddLoader`, `no block kind` — this build cannot record `blockKind`/`dataFlow` and has no `sys create` codegen |
| `/Users/robinhultman/dev/intropy/tooling/intropy-cli/bin/intropy` (local dev build) | built 12:22 | contains `intropy.dev/block-kind`, `no block kind`, `AddLoader` |
| `order-extractor/.intropy/scaffold.json` | 12:23 | has `blockKind` → dev build |
| `order-loader/.intropy/scaffold.json` | 12:24 | no `blockKind` → Homebrew 0.7.0 |
| `system-host/.intropy/scaffold.json` | 12:25 | dev build (0.7.0 has no `sys` verb) |

So chapter 2's command was run as the tutorial literally prints it (`intropy int create loader ...` → stale 0.7.0 from PATH), while chapters 1 and 3 were run with `./bin/intropy`. `blockKind`/`dataFlow` support is still **uncommitted** in the CLI working tree (`git status`: modified `internal/template/{create.go,scaffold.go,dependencies.go}`, untracked `internal/system/`, `cmd/intropy/sys*.go`), which is why the released 0.7.0 lacks it.

Two independent things worth noting for a fix: (a) adding `"blockKind": "loader"` and `"dataFlow": "out"` to the loader record makes `sys create` pick it up; (b) `writeSystemClassFile` (`internal/system/codegen.go:71-74`) overwrites an existing `OrderFlowSystem.cs` and refuses to create one, so re-running `sys create` over the existing `system-host/` will need the force path for the already-populated output dir.</result>
