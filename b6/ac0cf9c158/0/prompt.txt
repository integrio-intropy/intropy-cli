# Implementation Plan: `.From(...)` / `.To(...)` in the generated system definition

## Design decisions (with rationale)

### D1 — Connector name: template-derived, per-block unique (`&lt;appId&gt;-source` / `&lt;appId&gt;-destination`)
New `spec.values` entry in extractor/loader `template.yaml`:
- extractor: `connector: '{{ .name | kebabcase | replace "." "-" }}-source'`
- loader: `connector: '{{ .name | kebabcase | replace "." "-" }}-destination'`

Rationale: the expression is identical to the `appId` derivation, so connector uniqueness rides on the appId-uniqueness check Assemble already enforces. A shared fixed name ("source") would silently merge two extractors' connectors into one `ConnectorResource` (UsedBy union) and one folder — wrong default. No new user parameter: the connector name is intrinsic plumbing at scaffold time (per `Refs.cs:106-115`, what/how is a resolution concern); a rename to a semantic name ("pim") is a post-scaffold edit. Values flow through the generic scaffold `values` map, so no Go struct changes on the read path.

### D2 — sys create resolves the default: FILE transport, via new `Transport.File(rootPath)` + `ConnectorRef.Define(name, transport)`
Aspire hard-fails on unresolved connectors (`IntropyAspire.cs:61-70`), so leaving ITP107-unresolved connectors would break the F5 golden path. Emitting `Transport.Custom("bindings.localstorage")` cannot carry `rootPath` (Generation builds binding metadata only from the DevManifest, keyed by external system — `Generation.cs:110-134` — and the default connector has none). So Intropy.Topology gains:

1. `FileTransport` record: `DaprType =&gt; "bindings.localstorage"`, `SupportsInput/Output =&gt; true`, plus `public string RootPath { get; }`; factory `Transport.File([ConstantExpected] string rootPath)`; `[JsonDerivedType(typeof(FileTransport), "file")]`.
2. `ConnectorRef.Define(string name, Transport transport)` overload (transport known, external system deferred) — today only `(name)`, `(name, system)`, `(name, system, transport)` exist (`Refs.cs:146-178`).
3. `UnresolvedConnectorRule` (ITP107, `ConnectorCapabilityRules.cs:74-105`): skip the "external system" missing branch when `connector.Transport is FileTransport` — a local folder *is* the endpoint; there is no external system to resolve. Otherwise the freshly assembled golden-path system warns on every `check`. (Flagged below as the one library-contract change to confirm with the user.)
4. `TopologyGenerator.BindingComponent`: when transport is `FileTransport`, emit `("rootPath", RootPath)` metadata first (dev metadata from the manifest still appends). Recommended: in the Dev profile absolutize with `Path.GetFullPath(RootPath)` (dev artifacts are per-run temp files; the sidecar cwd is not guaranteed to be the host dir), emit verbatim for Prod.

### D3 — System-level test folders: `&lt;system-host&gt;/local/storage/&lt;connector&gt;/`, created by `sys create`; overlay naming fixed in templates
`system-host/skeleton/.gitignore:485` already ignores `local/storage/`. `sys create` runs `os.MkdirAll` for each connector folder after rendering (so the extractor's first `list` poll doesn't error on a missing dir).

The overlay trap is real and must be fixed in the templates: generated binding YAML is named `binding.&lt;connector&gt;` (`Resources.cs:45`), but the component-local files are named `inbound`/`destination`, so ComponentOverlay (keyed on `metadata.name`) would *add* the generated component instead of replacing the local one, and the app (Constants) would keep using the local folder. Fix: make the local component name and the app's binding-name constant both `binding.{{ .connector }}`:
- `extractor/skeleton/local/dapr-components/inbound.yaml.tmpl`: `metadata.name: binding.{{ .connector }}`, `rootPath: "./local/storage/{{ .connector }}"` (component-local path for standalone runs — "same names, different backing", exactly ComponentOverlay's documented contract).
- `loader/skeleton/local/dapr-components/destination.yaml` → `destination.yaml.tmpl`, same treatment.
- `Constants.cs.tmpl` (both): `InboundBindingName` / `DestinationBindingName` = `"binding.{{ .connector }}"`. Keyed adapter keys ("source"/"destination") stay unchanged. Dapr component names are DNS-subdomains; dots are legal (cf. generated `binding.&lt;name&gt;` already in the library).
- Sync the folder references in `Taskfile.yml.tmpl` (`INBOUND_DIR: ./local/storage/inbound` etc.), `README.md.tmpl`, `AGENTS.md.tmpl`.

### D4 — Codegen emits `Connectors.cs` + From/To lines, gated on a template placeholder
New generated file (mirrors Topics.cs; namespace-less; only `using Intropy.Topology;`):

```csharp
using Intropy.Topology;

/// &lt;summary&gt;The system's connectors: the named ports its edge blocks reach the outside world through. Default: local file folders under local/storage/.&lt;/summary&gt;
public static class Connectors
{
    /// &lt;summary&gt;Local file connector 'order-extractor-source' (folder ./local/storage/order-extractor-source). Resolve to a real external system + transport when known.&lt;/summary&gt;
    public static readonly ConnectorRef OrderExtractorSource = ConnectorRef.Define("order-extractor-source", Transport.File("./local/storage/order-extractor-source"));

    /// &lt;summary&gt;Local file connector 'order-loader-destination' (folder ./local/storage/order-loader-destination). ...&lt;/summary&gt;
    public static readonly ConnectorRef OrderLoaderDestination = ConnectorRef.Define("order-loader-destination", Transport.File("./local/storage/order-loader-destination"));
}
```

System class lines (API verified against `ComponentBuilders.cs:41-45,132-144`):

```csharp
builder.AddExtractor("order-extractor").From(Connectors.OrderExtractorSource).Publishes(Topics.Orders);
builder.AddLoader("order-loader").Subscribes(Topics.Orders).To(Connectors.OrderLoaderDestination);
```

Compatibility gate (mirrors the existing `writeSystemClassFile` placeholder gate, `codegen.go:72-76`): if the rendered system-host template left no `Connectors.cs` placeholder, the template release predates connectors — warn, skip Connectors.cs, and emit legacy (no-From/To) system-class lines. This keeps `--version &lt;old-tag&gt;` working, and protects against generated code referencing `Transport.File` that the pinned `Intropy.Topology` 0.1.0 package doesn't have.

### D5 — Repo split and sequencing
1. **Intropy.Topology** first (new API, ships as a package version bump — the system-host csproj pins `Intropy.Topology.Aspire`/`Generation` at `0.1.0`).
2. **intropy-templates** second (connector value, `binding.{{ .connector }}` renames, system-host `Connectors.cs.tmpl` placeholder + package version bump + fix `examples/*.yaml` missing required `contract`). New release tag.
3. **intropy-cli** last (assemble/model/codegen/summary + tests). The CLI reads `connector` from the generic values map — no coupling beyond the placeholder gate.

### D6 — Back-compat: missing `connector` value → warn + assemble without From/To (never default)
"Scaffold records never lie": a CLI-side default (`&lt;appId&gt;-source`) would describe a binding the old rendered code doesn't use (its Constants hardcode `"inbound"`, its local YAML is named `inbound`). The `pubsub` precedent doesn't apply — that default matched what old skeletons actually rendered; a connector default would not. So: warn (`"no connector recorded — re-scaffold with a newer template release to wire From/To"`) and emit the component exactly as today. This is valid topology: a loader without `To` is explicitly legal (decision 0008, `CompletenessRules.cs:5-10`) and an extractor only *must* publish (ITP206). Also skip such components in Connectors.cs.
