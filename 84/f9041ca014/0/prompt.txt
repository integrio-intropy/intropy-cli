 What this is (and isn't)

 The CLI's message wiring already shipped: --subscribe/--publishes resolve registry
 messages, snapshot channels into scaffold-record blocks, assembly consumes blocks offline,
 sys create emits a messages payload section, and internal/topology round-trips
 messagegroups opaquely. It was all built and tested against fixture templates — "what the
 template PR will ship." This workstream swaps fixtures for the real library, proves the
 vocabulary meets, and builds the harness the program's Gate G1 runs. Expected code change:
 minimal. The deliverable is proof plus a drift list, not a feature.

 Read first

 - internal/template/wiring.go, create.go, scaffold.go — the shipped contract: block shape,
   intropy.io/message-params label, seeding and direction gates.
 - internal/system/{assemble,blocks,payload,update}.go — assembly of block-shaped records,
   the payload's messages section, mergeWiring.
 - internal/system/real_template_e2e_test.go — the existing real-template harness
   (INTROPY_TEMPLATES_DIR, //go:build e2e). This is your primary extension point.
 - internal/topology/topology.go — graph JSON decoding; messagegroups is []json.RawMessage
   by design.
 - The templates agent's output: a feature branch/checkout of intropy-templates with
   message-first system-host, extractor, loader.

 Locked inputs (from the program owner)

 - T1 — templates location: <PATH OR BRANCH> of the message-first templates checkout. Point
   INTROPY_TEMPLATES_DIR at it.
 - C5 — graph JSON is frozen: apiVersion topology.intropy.io/v1, topics[] retained,
   messagegroups[] additive. No bump.

 Coordination rules (asymmetric — read carefully)

 1. This repo owns the contract; the contracts are released. The block shape, message-params
    label, and payload vocabulary shipped in a released CLI. If the templates don't meet
    them, that's templates-side drift — report it. If the CLI genuinely got the contract
    wrong, that's a program-level escalation: additive-only changes may be proposed,
    breaking changes go to the program owner. Never silently edit the contract to make a
    test pass.
 2. Drift is a first-class deliverable. Every mismatch you find goes on the drift list with:
    which side, which contract, what each side does today, and your recommended fix. An
    empty list at the end is a valid — excellent — outcome.
 3. The e2e harness renders; it does not dotnet build. Building rendered hosts against the
    topology prerelease is the templates agent's and the gate's job. Your assertions are on
    rendered text and record shapes.
 4. Do not touch deploy/manifests behavior or the dashboard's opaque messagegroups handling
    beyond verifying round-trip.

 U1. Real-library intake: int create against the real manifests

 Goal: prove int create extractor --publishes <msg> / int create loader --subscribe <msg>
 pass the message-parameters gate against the real template manifests, not fixtures.

 Files: internal/template/create_test.go, cmd/intropy/int_create_test.go — add real-manifest
 cases alongside the fixture ones (keep fixtures; they pin the contract). Use the existing
 local-template override seams (INTROPY_TEMPLATES_DIR / template.SourceOptions) rather than
 mocking.

 Test scenarios:
 - Happy path: both flags against the real manifests seed message parameters and write
   correctly-shaped subscribe/publishes blocks to .intropy/scaffold.json.
 - Error path (unchanged behavior): --subscribe against extractor and --publishes against
   loader produce the direction errors; either flag against a manifest without the label
   produces ErrNoMessageParameters with the "check the pinned template version" guidance.
 - Error path: seeded value conflicting with an explicit --set fails with the seed-conflict
   error, not an overwrite.
 - Edge: legacy flat-parameter scaffolding against the real manifests still renders (the
   tolerance path the templates keep).

 Verification: new cases green; fixture suite untouched and green.

 U2. sys create e2e: message-first system-host render

 Goal: the assembled payload renders through the real message-first system-host template
 into a correct declaration.

 Files: internal/system/real_template_e2e_test.go.

 Test scenarios:

   .Publishes(Messages.*) / .Subscribes(Messages.*), no Topics.cs.
 - Legacy: topics-only payload (flat records) → the template's fallback path renders a valid

 - Edge: transactional-only payload → no Messages.cs, no contracts dependency.
 - Regression: the unknown-kind fail branch still aborts rendering loudly.
 - Pin: the rendered api-service branch (loader-halfling) is byte-identical to before — it
   stays until WS-3.3.

 Verification: INTROPY_TEMPLATES_DIR=<T1> go test -tags e2e ./internal/system/ -run
 TestRealSystemHost -v green.

 U3. sys update e2e: re-render and orphan merge against the real template

 Goal: an existing host moves onto the message-first template, and a block-shaped orphan

 Files: internal/system/update_test.go, plus an e2e case in real_template_e2e_test.go if the

 - Error path: failed render leaves the host record un-rewritten (the honest-baseline
