## 2. The flow view

`/Users/robinhultman/dev/intropy/tooling/intropy-cli/web/src/components/FlowView.tsx` (714 lines) — the whole thing.

**Data it renders.** Two fetches on mount (161-167):
- `api.flow()` → `GET /api/flow` → `IntegrationDetail[]` (scaffold records + dapr components + pipeline step filenames).
- `api.topologies()` → `GET /api/topology` → `TopologyReport { topologies: Topology[], errors?: string[] }`.

The declared topology is the **only** source of nodes and edges. `/api/flow` is used *only* to (a) build the system dropdown with counts, and (b) join a declared component name to a scaffolded integration path so clicking selects it (`nodeId` map, 398-407). Comment at 218-219 is explicit: "Only a declared topology is drawn — there is no inferred fallback." A system with no record renders the empty state (299-304).

**Schema (`topology.intropy.io/v1`, kind `SystemTopology`).** Go: `/Users/robinhultman/dev/intropy/tooling/intropy-cli/internal/topology/topology.go`; mirrored TS: `web/src/api.ts:232-373`.

```
Entry { path }            // root-relative system dir, injected by the CLI (handlers.go:322)
Topology {
  apiVersion, kind, system
  components[] { name, kind, subscribes[]{pubsub,topic}, publishes[]{pubsub,topic},
                 ports[]{port, direction:"in"|"out"}, provides[], consumes[] /*opaque json.RawMessage*/ }
  topics[]    { pubsub, topic, contract?, publishers[], subscribers[] }   // lookup table
  ports[]     { name, externalSystem?, directions[], usedBy[] }          // lookup table
  contracts[] { name, kind, shortName, mediaType, fingerprint, schema /*raw JSON Schema*/ }
  apis[]      // opaque
  messageDocs?: Record&lt;portName, MessageDoc&gt;   // CLI-merged, NOT host-declared
}
```
Wiring is **inline edges on each component** — there is no top-level edge list. `topics[]`/`ports[]` are metadata tables the inline refs resolve against. Anything opaque (`apis`, `provides`, `consumes`) is `json.RawMessage` passed through unrendered because the shape isn't final (topology.go:46-50).

**How nodes/edges are drawn.** React Flow (SVG edges + DOM nodes), not raw SVG/canvas. `buildDeclaredGraph(topo, items)` at **FlowView.tsx:379-626** is the entire layout engine, hand-rolled:
1. Build `topicMeta` / `portMeta` lookup maps (387-390).
2. Node IDs: component → matched integration path if a scaffold exists, else `component:&lt;name&gt;` (402-407); topic → `topic:&lt;pubsub&gt;/&lt;topic&gt;` (393).
3. Collect unique topic refs and internal flow edges from inline `publishes`/`subscribes` (411-425).
4. **Longest-path layering** (Kahn relaxation, 431-457) over internal edges → `depth` map = column index. Cycles land in column 0 rather than failing.
5. Deterministic geometry from constants at lines 49-60: `NODE_W 300`, `NODE_H 84`, `COL_GAP 28`, `ROW_GAP 28`, `GROUP_HEADER 44`, `GROUP_PAD 20`, `INFRA_W/H 200/76` (topics), `EXT_W/H 184/72`, `EXT_GAP 96`, `EXT_VGAP 24`. `place(depth)` (468-471) assigns the next free row in a column.
6. A `group` node (517-525) is the system boundary, `draggable:false, selectable:false`; components and topics are its children (`parentId: groupId, extent:'parent'`).
7. Edges (530-559): publish = component `ext` handle (right) → topic `in`; subscribe = topic `out` → component `in`. All with `MarkerType.ArrowClosed` and `className:'rf-edge-ext'`.
8. Externals (ports) sit **outside** the group (566-623): direction `in` → placed left of its component; direction `out` → stacked below the component's column via `belowY(col)`. Deliberate to avoid whole-diagram crossings (comment 561-565).

Handles: IntegrationNode has target `in` (Left), source `infra` (Bottom), source `ext` (Right) — lines 656-658. TopicNode: target `in` Left, source `out` Right. **Caching model** (`apiServer`, handlers.go:46-74):
- `topoMu` / `topoLoaded` / `topoEntries` / `topoErrs`: the topology is computed **once, lazily on first request**, because it runs `dotnet build` + `dotnet run -- graph` per host. `cachedTopologies(ctx, force)` (315). `warmTopologies()` (348) computes in a detached goroutine so the catalog endpoint never queues behind a build.
- `depMu` / `depStates map[path]deployState`: per-integration, `deployStateTimeout = 1 minute` (43) — the bound exists to release the shared GitOps checkout lock, not for the browser.
- `createMu`: serializes create runs (two renders of the same name would race, and each downloads a tarball).
- Message docs are re-read from disk **on every request** (`topologyReport`, 298-310), so editing a `messages/*.md` shows up on browser refresh without re-running graph verbs.

The only client-side timer: `Catalog.tsx:33-34` `PENDING_RETRY_MS = 5000`, `PENDING_RETRY_CAP = 36` — retries a `topologyPending` catalog entry for up to 3 minutes while the background build finishes. Nothing else polls (deliberate; README lines ~950-957 explain why a background poll would deadlock the user's own `intropy deploy`).

**Topology provider** — `internal/dashboard/topology.go:25-42`: `hostGraphProvider(root)` → `template.ListSystemHosts(root)` → `topology.RunGraph(ctx, hostDir)` per host; `Entry.Path = filepath.Dir(h.Path)` (the system dir, since components are siblings of the host). Policy: never fail, report per host into `errs`. `topology.RunGraph` (`internal/topology/graph.go:28`) does `dotnet build` then `dotnet run --no-build --no-launch-profile --project &lt;hostDir&gt; -- graph`, decodes stdout, `GraphTimeout = 5 * time.Minute`. `Decode` rejects any other `apiVersion` outright (topology.go:136-146).

## 5. Existing write/POST endpoints

Three, all in `newHandler` (handlers.go:138-157):

1. **`POST /api/topology/refresh`** — re-runs graph verbs. Writes nothing to disk (runs `dotnet build`).
2. **`POST /api/deploy/{path...}`** — re-runs `deploy status`. Refreshes a shared GitOps checkout under an exclusive lock; read-only w.r.t. the workspace.
3. **`POST /api/templates/{name}/create`** — **the only endpoint that writes files.** Renders a skeleton + its dependencies into the workspace and writes `.intropy/scaffold.json`.

There is no auth, no CSRF token, and no `Origin` check — the server binds `127.0.0.1` by default (`dashboard.go:47`) and that is the entire threat model. Something to weigh if the create surface grows.

### 1.2 Extend `resolveCreate` — validation rules spelled out

Keep the existing name rule untouched, add dir handling before the join:

1. `Name`: unchanged — non-empty, no `/` or `\`, not `.`/`..` (existing lines 186-188).
2. Normalize `Dir`: `""` → `"."`. If `"."`, behavior is byte-for-byte today's (`filepath.Join(s.root, req.Name)`), so existing clients/tests are unaffected.
3. Otherwise split `Dir` on `/` and validate **every segment** with one rule (mirror `validateTemplateName`'s posture, create.go:254): reject empty segments (`"a//b"`, trailing `/`), `.`, `..`, any segment starting with `.`, and any `\` anywhere in `Dir`. Also reject a rooted `Dir` (`strings.HasPrefix(dir, "/")` is caught by the empty-first-segment rule — note it in the test table).
4. Join: `outputDir = filepath.Join(s.root, filepath.FromSlash(dir), req.Name)` and keep the existing absolute-equality assertion, generalized:
   `outAbs == filepath.Join(rootAbs, append(segments, req.Name)...)` — the same "output would escape the workspace root" refusal.
5. **Existence rule (decision):** `filepath.Join(s.root, dir)` must `os.Stat` as an existing directory → 422 (`"directory %q does not exist under the workspace root"`). This is the minimal posture: the endpoint can only render into directories the served workspace already has. Do **not** require a known system/scaffold in the dir — it would block the legitimate "first block into a hand-made system dir" case and buys little, since writes are already confined under root. (Flag: if you want the stricter rule later, check `dir` against `scan()`'s systems map ∪ observed `systemPath`s.)
6. Optional hardening worth one extra line: `filepath.EvalSymlinks` on the dir and assert the resolved path still has `rootAbs` (resolved) as prefix — the current code shares this (theoretical) symlink gap for `Name`, so it's consistent either way; note it in the commit message if skipped.

No response-shape change: `result.OutputDir` already goes through `s.relPath`, so the client gets `"domain/sys/new-extractor"` — exactly the identifier space `/api/flow` uses, which the frontend needs for the ghost join.
